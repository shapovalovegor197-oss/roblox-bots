# Запуск фермы на втором компьютере

Бот — обычный Python-скрипт. Claude Code для фарма не нужен, он нужен только
когда что-то сломалось и надо чинить.

Проверено на десктопе (Xeon E5-2650 v4, 16 ГБ, RTX 4060). На ноуте с Vega 8 и
8 ГБ круги будут медленнее — см. «Чего ждать от слабой машины» в конце.

---

## 1. Что поставить

* **Python 3.12** (на 3.13 не проверялось), при установке отметить «Add to PATH»;
* **Git**;
* **клиент Roblox** — обычный, из Microsoft Store или с сайта.

```powershell
git clone git@github.com:shapovalovegor197-oss/roblox-bots.git
cd roblox-bots
pip install -r requirements.txt
```

Если SSH-ключа на ноуте нет, склонировать по HTTPS:
`git clone https://github.com/shapovalovegor197-oss/roblox-bots.git`

## 2. Аккаунт

`config/accounts.json` в репозитории НЕТ и не будет — там куки, то есть полный
доступ к аккаунту. Скопировать файл с рабочей машины руками (флешкой, не через
мессенджер) либо собрать заново из `config/accounts.example.json`.

**Один аккаунт нельзя держать в двух местах.** Если на десктопе фармит `raven`,
ноуту нужен другой — `farm-1` или `sklad-1`. Иначе второй клиент выкинет первый.

## 3. Разовая калибровка на этой машине

Запустить игру и войти в неё:

```powershell
python run.py launch farm-1
```

Дальше по порядку, каждая команда печатает результат числом:

```powershell
python scripts\fix_window.py      # окно клиента к 1280x720 — от него зависят ВСЕ доли кадра
python scripts\pitch_home.py      # на сколько опускать камеру после вида сверху
```

`pitch_home.py` печатает таблицу «возврат → отличие от исходного». Взять число
с наименьшим отличием и вписать в `src/brainbot/farm.py`, поле
`FarmTuning.view_pitch_back` (на десктопе вышло 170).

**Поворот камеры бот меряет сам** при каждом запуске круга — ползунок
чувствительности в клиенте можно не трогать.

## 4. Запуск фермы

```powershell
python scripts\farm_loop.py 480 5000 10
```

Три числа: сколько минут работать, минимальный доход брейнрота для покупки
($/с), сколько перерождений сделать.

Круг устроен так: запереть базу → пройти по ряду (собрать деньги, каждый третий
проход ещё и продаёт слабых) → выйти к ленте → покупать 35 секунд → домой.
Цели перерождения покупаются вне очереди по любой цене.

## 5. Как следить, не трогая мышь

* `var\farm_status.json` — сводка: круги, локи, покупки, ребёрны, сбои, кэш;
* вывод скрипта — построчно, что происходит;
* `var\screens\` — кадры на каждом отказе, по ним и разбираемся.

Остановить: `Ctrl+C` в окне запуска либо
`Get-Process python | Stop-Process -Force`.

**Бот уступает ввод, как только тронешь мышь или клавиатуру**, и возвращается
через 12 секунд тишины. Работать на этой машине параллельно не выйдет.

## 6. Если что-то не так

| Признак в логе | Что делать |
|---|---|
| `до ленты не дошёл` подряд | `python scripts\fix_window.py` — окно съехало |
| `сверху пад не опознан` | сменилось освещение; кадр в `var\screens`, смотреть глазами |
| деньги скачут в разы | `python scripts\bench_offline.py` — стенд по сохранённым кадрам, без игры |
| `лок не вышел` подряд | камера уехала: перемерить `pitch_home.py` |
| бот «закрывает окно» в пустом мире | ложный крестик; кадр покажет, что он принял за кнопку |

Стенд `bench_offline.py` гоняется **без игры** и проверяет чтение денег и поиск
крестика по сохранённым кадрам — с него и начинать любой разбор.

## 7. Чего ждать от слабой машины

Ноут — Ryzen 5 3500U с Vega 8 и 8 ГБ. Игра пойдёт (бот целится в 20 FPS), но
сверху ложатся захват кадров и OCR:

* круги будут длиннее, сбоев больше;
* тайминги ходьбы заданы в секундах удержания клавиши, поэтому от FPS почти не
  зависят — а вот распознавание на просадках промахивается чаще;
* если греется — в `config/settings.json` есть `optimize.target_fps`, можно
  опустить до 15.

Одновременно с фармом на этой машине лучше ничего не делать.
