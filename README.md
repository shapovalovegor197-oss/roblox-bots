# roblox-bots

Личный проект. Боты для Roblox / Steal a Brainrot: **хранение** брейнротов на своих
аккаунтах-складах и **передача** себе и друзьям.

К `gg` (Starpets → GGSel) отношения не имеет — отдельные аккаунты, отдельная история.

## Быстрый старт

```powershell
python -m pip install -r requirements.txt
python run.py doctor
```

`doctor` проверяет всё разом: зависимости, клиент Roblox, мьютекс, открытые окна,
конфиг и живость кук.

### Аккаунты

```powershell
copy config\accounts.example.json config\accounts.json
```

Куку `.ROBLOSECURITY` брать в браузере: F12 → Application → Cookies → roblox.com.
`accounts.json` в `.gitignore`, в логи куки не попадают — их вырезает фильтр в `log.py`.

## Оптимизация: откуда берутся сессии

**Экран больше не лимит.** Захват идёт через Windows.Graphics.Capture (`zbl`) — по
hwnd конкретного окна, а не снимком экрана. Перекрытые окна снимаются нормально,
проверено на живом клиенте. Поэтому окна складываются лесенкой друг на друга
(`window.layout: stack`), а не раскладываются по монитору: на 1920×1080 сеткой
влезало бы два-три клиента, и на этом всё.

Режим `tile` остался для отладки, когда хочется видеть все окна глазами.

**Клиент урезан по кадрам.** `optimize` пишет `ClientAppSettings.json` во все версии
клиента. Главный флаг — `DFIntTaskSchedulerTargetFps: 20`: боту не нужно 60 кадров,
ему нужен стабильный UI, а 20 вместо 60 — это втрое меньше работы GPU. Дальше по
списку тени, постобработка, сглаживание, воксельный свет, текстуры на минимум и
выключенная телеметрия.

Настройки пишутся заново перед каждым запуском: обновление клиента создаёт новую
папку версии, где их нет.

**Ядра поделены.** Roblox однопоточный по главному циклу, ядер 24. Без привязки
планировщик таскает клиентов между ядрами и рушит кэш. Каждому клиенту — свой
набор ядер, приоритет `below`, первые 4 потока оставлены системе, боту и захвату.

**Что осталось лимитом.** Только ОЗУ. Клиент берёт ~1.5 ГБ на загрузочном экране и
больше в людном сервере. `capacity` меряет по живым клиентам и считает, сколько
влезет — сейчас, после закрытия лишнего и после добивки памяти.

## Если клиент не входит на сервер

Симптом: висит на «Joining server», потом `Connection Failed, Error Code: 279`.
Разбираться нужно по логу клиента, а не по ощущениям:

```powershell
$f = Get-ChildItem "$env:LOCALAPPDATA\Roblox\logs" -Filter "*_Player_*.log" |
     Sort-Object LastWriteTime -Desc | Select-Object -First 1
Select-String -Path $f.FullName -Pattern "UDMUX Address|Connection accepted|Failed to connect"
```

`Connection accepted from ...` — вошли. `Failed to connect ..., no response` — нет.

Три причины, все встречались вживую 28.08.2026:

**1. VPN заворачивает игровой трафик.** Игра ходит по UDP (RakNet на UDMUX,
адреса вида `128.116.X.33`). Туннель делает свой NAT, и ответы теряются.
Правило `process_name → direct` в конфиге sing-box **не помогает**: пакет всё
равно заходит в TUN и уходит наружу уже от sing-box. Помогает маршрут в таблице
ОС — сеть Roblox тогда в туннель не попадает вообще:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\roblox-direct-route.ps1
```

Снять: тот же скрипт с `-Remove`. Маршрут постоянный, переживает перезагрузку и
пересборку конфига VPN-клиента. Работает, пока Roblox не заблокирован у
провайдера напрямую — на этой машине проверено, что не заблокирован.

**2. Roblox обновился, а клиент остался старый.** Обновление ставится молча,
переключает протокол, и работающий старый клиент перестаёт попадать на серверы —
на любом датацентре. Снаружи выглядит как поломка сети. Лечится перезапуском
клиента; супервизор ловит смену версии сам и перезапускается.

**3. Мы сами придушили клиент.** `optimize --pin-live` режет клиенту ядра и
опускает приоритет — живому клиенту этого хватает, чтобы словить таймаут RakNet.
По умолчанию `optimize` живые клиенты не трогает. Если всё же придушили:

```powershell
python run.py unpin
```

## Как это устроено

```
mutex · launcher · window    поднять клиент под нужным аккаунтом, найти его окно
capture · vision · inputs    смотреть в окно и действовать в нём
session                      аккаунт + окно + всё вышеперечисленное
supervisor                   держать это живым сутками
scenarios/                   что именно делаем: трейд, фарм, ребёрн
```

Два принципа, на которых всё держится:

**Никакой инъекции.** Память процесса Roblox не трогаем — отсюда и выбор
«зрение + ввод». Hyperion не видит того, чего нет в его процессе.

**Координаты относительно окна, не экрана.** Окна можно двигать и раскладывать,
шаблоны от этого не ломаются. Ломает их только смена размера окна — поэтому размер
фиксирован в `config/settings.json` и выставляется при каждом запуске.

## Шаблоны

`templates/*.png` — вырезки элементов интерфейса, имя файла = имя шаблона в коде.
Какие нужны для передачи — перечислено в шапке `src/brainbot/scenarios/trade.py`.

Нарезка: снять кадр (`shot --resize`), потом `cut` — выделить мышью, ввести имя,
повторить. Проверить: `find <имя>` рисует рамку поверх живого окна.
